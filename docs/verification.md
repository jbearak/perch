# Manual verification checklist

These checks cannot be automated in Perch's CI or were not possible where Perch was built. Each one says what to do and what should happen. Status is "not run" until a maintainer runs it and records the date, the versions and the result.

| Check | Steps | Expected | Status |
|-------|-------|----------|--------|
| Remote-SSH survival | From VS Code, open a Remote-SSH window to a Linux host. Open a Persistent shell and an R session. Disconnect the network for longer than the reconnection grace period, or close the window. Reconnect. | Both sessions are listed and restore with their screens. | not run |
| VS Code server update | On a Remote-SSH host with live sessions, update VS Code so the server is replaced. Reconnect. | Sessions survive and the new extension attaches to them. | not run |
| Linked `VSCODE_IPC_HOOK_CLI` over Remote-SSH | Add `VSCODE_IPC_HOOK_CLI` to `perch.linkedEnvironment`. In a new Perch shell on a remote host, close the window, reopen it, reattach, run `code somefile`. | The file opens in the window now attached. A local window has no CLI socket (VS Code sets the variable only in remote windows), so the local test checks the link with sockets of its own. | not run |
| Adoption after an extension host restart | With Perch terminals open, run "Developer: Restart Extension Host". | The same terminals stay and are adopted; no duplicates open. | not run |
| Persistent shell from the profile picker | Pick "Persistent shell" from the terminal's profile menu, run `sleep 1000`, close the terminal, then reload the window. | The session is created with `perch.shell` (default `$SHELL`, with `-l` on macOS), survives the close, and is not reopened after the reload because the user closed it; opening it from the Perch view reattaches with its screen and history. The tests start the profile through VS Code's "Create New Terminal (With Profile)" command and through another extension's provider with `prepareLaunch`, not through the picker's menu itself. | not run |
| Restore after a window reload | Open two Perch terminals in a workspace, run "Developer: Reload Window". | Both come back once, attached here; the tests cover this across two VS Code launches, not a reload. | not run |
| Shell integration after reattach | Install VS Code shell integration manually in zsh. In a Perch shell, run `sleep 30`, close the terminal, reopen the session during the sleep. | Command detection marks the command when it finishes. Record what happens either way. | not run |
| Restore in Terminal.app and iTerm | `perch attach --restore screen` into a session running `vim`, then quit `vim`. | Screen, cursor and the primary screen after `vim` are right; existing scrollback is kept. | not run |
| Registry installs | Install the published extension from the Marketplace and from Open VSX: locally on macOS and Linux, and from Windows and macOS through Remote-SSH to Linux. | The right platform build installs on the host that runs the workspace extension; the binary runs. | not run |
| Ad-hoc signature after registry download | On macOS, install the published extension from each registry and create a session. | The binary runs without a Gatekeeper prompt. | not run |
| darwin-x64 binary | On an Intel Mac, install the darwin-x64 VSIX and create, attach to and kill a session. | Works; CI only cross-compiles this target. | not run |
| Epilogue in other terminals | `perch attach` in Terminal.app, iTerm and tmux to a session running `vim` with mouse reporting on; detach with `Ctrl-\`. | The shell afterwards has no mouse reporting, no bracketed paste, a visible cursor and the main screen. | not run |
| fish and reedline recordings | On a machine with fish and a reedline-based program, run `tests/fidelity/record.sh fish-right-prompt-recorded reedline-recorded` (with `PERCH_REEDLINE` set to the program), then `node tests/fidelity/run.mjs` and commit the fixtures. | The recordings pass the harness on all three xterm.js versions. The synthetic `fish-right-prompt` and `reedline-redraw` fixtures stand in until then. | not run |
| Detach key under the kitty keyboard protocol | In kitty or Ghostty, `perch attach` to a session running a program that turns on the kitty keyboard protocol with all keys as escape codes (for example `nvim` with it enabled), then press `Ctrl-\`. Repeat in iTerm with modifyOtherKeys on. | The client detaches each time; with `--detach-key none` the key reaches the program instead. The tests send the CSI-u forms but no real terminal produces them in CI. | not run |
| Kitty keyboard stack after restore | In kitty or Ghostty, `perch attach --restore screen` to a session where a program pushed several kitty keyboard flags (including a zero entry), then pop them one by one. | Each pop leaves the same flags as without Perch. | not run |
| Local window on Windows | Install the universal VSIX in VS Code on Windows and open a local folder. Open the Perch view and run "Perch: Show Command-Line Path". | The view says Perch needs a macOS or Linux host; nothing tries to run a binary; the status bar shows no count. | not run |
| Command-line copy on an NFS home without `flock` | On a cluster whose home directory is NFS without lock support, open two Remote-SSH windows with different extension versions. Run `$PERCH_BIN version` in a new terminal of each. | Each activation installs its own copy without the lock (the Perch output says so); the copy always runs; the newer version is back after the newer window reactivates. | not run |
| VSCodium and Rhodium | Install the VSIX in VSCodium (and Rhodium when it exists), locally and through its remote development extension. Create, attach to and kill a session; open the API from a test extension. | Same behavior as in VS Code. | not run |
| `SSH_AUTH_SOCK` through VS Code Remote-SSH | In a Remote-SSH window with agent forwarding, open a Persistent shell, reconnect from another machine or agent, reattach, run `ssh-add -l`. | Lists the new agent's keys. | not run |
| `perch doctor` on an NFS runtime directory | On a cluster, run `PERCH_RUNTIME_DIR=$HOME/perch-nfs-test perch doctor` with `$HOME` on NFS, then remove the directory. | The `flock` check fails (or passes only where the NFS server supports locks) and says to use a local directory. | not run |
| Stata | With Stata installed, run a long `do` file through Sight with Perch, close the window, reopen. | The session survives. Note whether the license seat stays held. | not run |
